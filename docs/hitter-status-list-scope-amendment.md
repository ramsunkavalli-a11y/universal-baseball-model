# Keep separate restrictions separate during status review

2026-10-04. Reviewing the first status ledger identified an implementation gap:
an explicit activation from the restricted list could clear a suspension even
though it did not report suspension reinstatement. The first module also omitted
plain suspension-clearing activations from its readable trace. Its decisions,
source seal and ledger remain intact. No model fits or forecasts used them.

The successor records independent suspended, restricted, administrative and
ineligible channels. A dated activation clears only its named channel. A plain
MLB activation may resolve the suspension channel under the existing reviewed
rule, never an unrelated named restriction. Finite duration refines the generic
record from the same event rather than creating a second restriction. A death
record cannot be cleared; permanent ineligibility requires explicit ineligible
reinstatement. Same-day incompatible evidence remains ambiguous, with no
transaction-ID ordering. Retirement remains separate.

The successor retains the same 83,300 source identities, cutoffs, employment
rules, literal listings, clinical spells and return report. It adds active
restriction channels and complete state-change traces. Availability flags reflect
all unresolved channels, not only the displayed summary state. Preserve unknown
return dates and distinguish calendar duration from game counts. A return report
must match the suspension event before it can describe that suspension.

Before integration, independently replay the successor ledger, show every
changed decision and walk the fixed fifteen cases through actual records and
unchanged forecasts. This corrects source logic; it cannot establish predictive
improvement, guarantee a job or certify medical recovery. Protected 2026 and
current explorers remain unchanged.
