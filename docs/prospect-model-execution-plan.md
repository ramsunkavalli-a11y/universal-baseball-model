Use the saved v8 forecasts and source lineage, without fitting a new model.

1. Reconcile labels, population membership and component units for the Rookie,
   DSL, Triple-A and observed-pitching groups. Separate league-routing and role
   artifacts from genuine predictive errors. Check whether reported position
   and level describe the intended origin exposure.
2. For each group and origin, report predicted versus observed arrival,

3. Compare errors for non-arrivals, brief MLB participants and substantial careers.

4. Inventory already available feature families, their source dates and coverage

## Stage 2: one bounded benchmark confirmation

Confirm the earlier feature conclusions under corrected folds, not by repeatedly
restarting the project. Write the exact feature manifest and comparisons before
running them. Shared core context must use only verified available fields.

One batch: basic context; context plus production; context plus existing pedigree;
context plus both; and the existing rich v8 candidate as a reference. Keep model
family/settings fixed for the four information comparisons. Shared context
includes exposure/history controls so production is not confused with simply
having more opportunities. Keep environmental treatment identical wherever
performance is compared. If the baseline manifests already correspond to saved
models, reuse those definitions rather than inventing near-duplicates.

Purpose: establish a defensible benchmark and identify whether the affected
production/pedigree claims survive. This batch is not a claim that those four
information sets exhaust baseball talent, nor that linear models exhaust the
usefulness of interactions. Sparse/absent pedigree stays unknown, not low quality.

Exit artifact: one paired comparison by origin, level and exposure, plus the
specific benchmark carried forward. Report uncertainty and magnitude together;
do not choose a model merely because it is first in a table.

## Stage 3: repair the identified prediction problem

Use Stage 1 evidence to choose the next bounded experiment. Current candidates
for diagnosis are inconsistent timing/opportunity, direct-value allocation across
levels, and role/path confusion. They are not three mandatory simultaneous rebuilds.

Compare the retained direct-value benchmark with a coherent career construction
if decomposition is the supported need: arrival timing, conditional opportunity
and production linked so better production can affect continued opportunity.
Do not multiply three unrelated averages and call that a joint model. Enforce
valid probability relationships and retain the possibility of brief, sustained,
unsuccessful and converted-role careers without assigning future roles in advance.

Additional inputs belong inside this same experiment, not a new direction.
Use the available verified feature families; if testing an incremental family,
hold the rest fixed. A small preregistered set of group-removal tests can examine
its contribution within the richer model. Redundant signals may substitute for
each other, so no increment is not proof the underlying baseball factor is
irrelevant. Use an already evaluated interaction-capable learner where needed;
do not repeat a wide algorithm tournament without evidence of an algorithmic
limitation. Exact candidates/tuning budgets are fixed in the experiment contract.

Park/opponent adjustment interprets observed performance and is distinct from
forecast destination environment. Country is not a preassigned national talent
curve; birthplace is not necessarily development history. Today's body weights
cannot become historical teen measurements. Missing contact coverage is not poor
contact. These are measurement constraints, not reasons to ban plausible inputs.

## Stage 4: decide once, with visible evidence

Every result must show:

- Identical evaluation populations and the intended outcome/horizon.
- Paired arrival probability scores, substantial-opportunity results, and
  delivered-value errors; a one-PA debut is not equivalent in value to a regular.
- Predicted/actual totals by year and level, not just a pooled total in which
  errors cancel. Investigate material deterioration; do not require every noisy
  subgroup point estimate to improve.
- Probability consistency, source coverage and chronology checks.
- Named false highs/lows plus their comparable groups. High-probability failures
  are expected occasionally; case anecdotes cannot override calibrated groups.
- Clear status: adopt the data/method correction, retain a research candidate,
  reject this implementation, or insufficient evidence. A failed implementation
  is not a finding that its underlying baseball idea is useless.

Set practical tolerances and uncertainty reporting in the experiment contract
before fitting, using the benchmark scale and data support. Do not change the
acceptance rule after seeing the result. A small average gain cannot excuse an
unresolved target error or large systematic allocation failure.

## Change control and reporting

New suggestions enter the inventory/backlog by default. Change the active plan
only for a demonstrated data/method defect, evidence that the current approach
cannot address the objective, or explicit user reprioritization. Record what
changed, the evidence, and which result it invalidates. A sensible new feature
or a compelling single-player story is not enough to restart the sequence.

At each checkpoint report: what was tested; against what; the numerical and
baseball interpretation; what changed in the actual model; what did not work;
the single next experiment and why. Keep artifact paths and technical detail
available without replacing the plain-language explanation.
